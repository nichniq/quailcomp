# DevTools UI Enhancement Plan

## Context

The devtools UI currently has a working file watcher dashboard and test specs viewer, but includes several placeholder tabs ("Metrics", "Admin", "Git") that show "Coming soon..." messages. The user wants to remove these placeholders and add several new functional pages:

1. **Remove placeholder tabs** - Clean up the Metrics, Admin, and Git tabs
2. **HTML Coverage Report page** - Display test coverage in a visual HTML format
3. **Enhanced Specs page** - Add test result indicators (pass/fail/skipped) to the existing test specifications
4. **Server Logs page** - Live stream of server logs
5. **Server Events page** - Live stream of server-sent events for debugging
6. **API Key Management page** - Create and manage API keys

## Current Architecture

- **UI Framework**: Vue 3 (Composition API) + TypeScript + Vite
- **Navigation**: Simple tab-based system using `activeTab` ref (no Vue Router)
- **API Communication**: Direct `fetch()` calls to `/api/*` endpoints
- **Real-time Updates**: Server-Sent Events (SSE) via `EventSource`
- **Backend**: Bun HTTP server on port 3001 (`devtools/ui/server.ts`)
- **Styling**: Scoped CSS with BEM-like naming conventions

**Key Files**:
- [devtools/ui/src/App.vue](devtools/ui/src/App.vue) - Main app component with tab navigation
- [devtools/ui/src/components/WatcherStatus.vue](devtools/ui/src/components/WatcherStatus.vue) - File watcher dashboard
- [devtools/ui/src/components/TestSpecs.vue](devtools/ui/src/components/TestSpecs.vue) - Test specifications viewer
- [devtools/ui/server.ts](devtools/ui/server.ts) - Backend API server
- [devtools/ui/src/types.ts](devtools/ui/src/types.ts) - TypeScript type definitions

### 4. Add Server Logs Page

**New files**:
- [devtools/ui/src/components/ServerLogs.vue](devtools/ui/src/components/ServerLogs.vue) - Live log viewer

**Files to modify**:
- [devtools/ui/src/App.vue](devtools/ui/src/App.vue) - Add 'logs' tab
- [devtools/ui/server.ts](devtools/ui/server.ts) - Add `/api/logs/stream` SSE endpoint
- [devtools/ui/src/types.ts](devtools/ui/src/types.ts) - Add log entry types

**Backend Implementation**:
- Create log streaming mechanism:
  - Option A: Tail the application log file (if one exists)
  - Option B: Hook into console.log/error and broadcast to SSE clients
  - Option C: Use a shared logger that emits to both console and SSE
- SSE endpoint sends log entries as they occur
- Include metadata: timestamp, level (info/warn/error), source, message

**Frontend Implementation**:
- Connect to SSE endpoint for real-time log stream
- Display logs in a terminal-like interface (monospace font, colored by level)
- Auto-scroll to bottom when new logs arrive (with pause option)
- Add filters: log level, search text, source/component
- Add "Clear" button to reset view
- Show connection status (connected/disconnected/reconnecting)
- Limit to last 1000 entries to prevent memory issues

**Pattern to follow**: Similar to WatcherStatus SSE connection, but focused on streaming text data.

### 5. Add Server Events Debug Page

**New files**:
- [devtools/ui/src/components/ServerEvents.vue](devtools/ui/src/components/ServerEvents.vue) - SSE debugger

**Files to modify**:
- [devtools/ui/src/App.vue](devtools/ui/src/App.vue) - Add 'events' tab
- [devtools/ui/server.ts](devtools/ui/server.ts) - Add `/api/debug/events` endpoint

**Backend Implementation**:

- Display event types, timestamps, and originating endpoints

### 6. Add API Key Management Page

**New files**:
- [devtools/ui/src/components/ApiKeys.vue](devtools/ui/src/components/ApiKeys.vue) - API key manager

**Files to modify**:
- [devtools/ui/src/App.vue](devtools/ui/src/App.vue) - Add 'api-keys' tab
- [devtools/ui/server.ts](devtools/ui/server.ts) - Add API key management endpoints
- [devtools/ui/src/types.ts](devtools/ui/src/types.ts) - Add API key types

**Backend Implementation**:
- Store API keys in a JSON file (e.g., `.devtools/api-keys.json`)
- Endpoints:
  - `GET /api/keys` - List all keys (masked, show only last 4 chars)
  - `POST /api/keys` - Generate new key
  - `DELETE /api/keys/:id` - Revoke key
  - `PUT /api/keys/:id` - Update key metadata (name, permissions)
- Key generation: Use crypto.randomBytes for secure random keys
- Store: `{ id, name, key (hashed), createdAt, lastUsedAt, permissions }`
- Only return full key once during creation (never again)

**Frontend Implementation**:
- List existing keys in a table: name, created date, last used, actions
- "Generate New Key" button → shows modal:
  - Input: Key name (required)
  - Input: Permissions/scopes (checkboxes)
  - Generate button → displays full key with copy button
  - Warning: "Save this key now, you won't see it again"
- Revoke action with confirmation dialog
- Edit name/permissions for existing keys
- Visual indicators: active/revoked status
- Show last 4 characters of key for identification

**Pattern to follow**: Similar to WatcherStatus for listing + forms for creation/editing.

## Technical Considerations

### Test Results Integration
The most complex feature is #3 (test results in specs). We need to:
1. Decide on test result storage (file vs in-memory)
2. Establish naming convention to map tests to specs
3. Consider running tests automatically or on-demand

**Recommendation**:
- Add a test watcher task that runs tests and stores results in `.devtools/test-results.json`
- Use file-based mapping: spec file `foo.spec.md` → test file `foo.test.ts`
- Display results from last run, add "Run Tests" button to refresh

### Log Streaming Implementation
For #4 (server logs), we need infrastructure to capture logs:

**Recommendation**:
- Create a `devtools/logger.ts` module that:
  - Wraps console.log/error/warn
  - Broadcasts to SSE clients
  - Maintains circular buffer of last 1000 entries
- Export `logger` instance for use throughout codebase
- Replace console calls in main app with logger calls gradually

### API Key Security
For #6 (API keys), security is critical:

**Recommendations**:
- Hash keys before storage (bcrypt or similar)
- Store in `.devtools/` directory (gitignored)
- Use UUIDs for key IDs
- Implement key rotation (expiry dates)
- Add rate limiting to key endpoints
- Consider environment variable for master admin key

### Performance
- Use circular buffers for logs (limit to 1000 entries)
- Implement SSE connection pooling/cleanup
- Add pagination for API key list if it grows large
- Consider virtualizing log display for smooth scrolling
